# 口播稿 → 画面清单

输入:一篇完整的口播稿(用户粘贴或给出文件),可选主题(默认 `neon`)。
输出:`storyboards/<视频名>.json`,并通过 `node scripts/validate-storyboard.mjs <清单> --script <口播稿文件>`(格式 + 渲染检查)。
用户的流程负责字幕、配音和最终组装;清单只管画面。

## 步骤

1. **保存口播稿**到 `storyboards/<视频名>.txt`(原样,不改字),后面校验要用。
2. **读组件目录** `catalog/catalog.json`:每个组件的 `kind`、`purpose`、`suitableFor`、`minDuration`、`variables`。只能用目录里的组件(或本次生成并写进 `newComponents` 的新组件)。
3. **切分画面**(见"规则"),每个画面一件事。
4. **选组件、提炼文案**,写清单(格式见"清单格式")。
5. **校验**:`node scripts/validate-storyboard.mjs storyboards/<视频名>.json --script storyboards/<视频名>.txt`。报错就改清单,直到输出 `storyboard OK`。渲染检查每个画面要跑一次,1 分钟的视频约几分钟;调整阶段可先加 `--no-render` 只查格式,最后一次必须跑完整检查。
6. **交付**:告诉用户清单路径、画面数与总时长、每个画面用了什么组件、`needs` 里需要他补的素材(录屏 / 截图)、有没有待确认的新组件。

## 规则

1. **按意思切分,不按句子切**:一个画面只讲观众要记住的一件事(钩子、要点、步骤、数字、对比、金句)。每个画面 3~8 秒,约 12~32 个字;太长拆开,太短的零碎句并到相邻画面。口播超过约 8.5 秒的画面校验会报错;手机录屏放宽到约 12.5 秒,再长就按步骤拆成几个录屏画面,每个画面在 `needs` 里写清这一段录什么。
2. **首尾固定**:第一个画面是钩子(`dy-scene-title` 或 `dy-hook-title`),前 3 秒亮出核心看点;最后一个画面是 `dy-scene-ending` 或 `dy-end-cta`。
3. **按 `suitableFor` 选组件**:找口播里的信号——列举几点用要点页,讲先后操作用步骤页或手机录屏,强调一个数字用大字页,两者对比用对比页,一句总结用金句页,解释名词用名词解释卡,给出提示词用提示词卡。几个都合适时优先整屏场景(`kind: scene`);但如果某个叠加组件的 `suitableFor` 明显更贴切(例如口播讲用 AI 前后的耗时变化,`dy-before-after` 比通用对比页更贴切),用它。
4. **同一主题用同一种组件讲完**:一段连贯的内容(例如一条时间线的几个年份、同一组步骤)不要拆给几种互不相干的组件;要么一个组件装下(步骤页、要点页),要么连续画面用同一个组件。
5. **避免单调**:不相干的内容,同一组件最多连续 2 次;同一主题的连续推进(规则 4,例如时间线逐年高亮、同一组步骤逐步高亮)不受这个限制。只在换话题处加转场(`transitionIn`),约每 3~4 个画面一次;同一主题的连续画面之间不加;第一个画面没有转场。
6. **文案提炼**:标题不超过 16 字;要点 3~5 条,每条不超过 14 字。文案是提炼的短句,不照抄口播。
7. **数字只能来自口播**:不换算、不推算(口播说"一个半小时到三分钟",不能写"快了 30 倍")。中文数字可以写成阿拉伯数字("一百万" 写 `100` 加单位"万","九十九点九" 写 `99.9`)。数字类变量(如大字页的 `value`、投票的 `pctA`)不能省略,省略会露出组件的示例数字;口播里没有这个数,就换一个不需要它的组件。
8. **显示文字的变量都要显式填写**:组件的默认值是示例文案(例如"来源:官方发布会"),漏填就会露出来。不想显示就写 `""`。颜色、主题变量可以不写。
9. **叠加组件**(`overlays`):只用 `kind` 为 `overlay` / `ui` 的组件,每个画面最多 2 个,用于情绪强调(花字)或补充信息;`at + duration` 不超过画面时长。
10. **不能用的组件**:转场只能写在 `transitionIn`;`dy-subtitle`(字幕由用户流程负责)、`dy-safe-zone`、`dy-progress-bar`、`dy-ai-badge`(全片组件,由组装流程挂载)不能出现在画面里。
11. **主组件是叠加类**(`kind: overlay`,透明背景)时,组装时要在下面垫 `dy-scene-bg`;交付时提醒用户。组件自带的固定文字(`purpose` 里会写明,如对比卡的『以前』『用 AI』)不要在变量里重复。
12. **录屏 / 截图**:口播在演示具体操作时用 `dy-rec-phone`(或截图用 `dy-scene-image-text`),`src` 留 `""`,在 `needs` 里写清楚要录什么。`cues` 的坐标要看到录屏才能定,先写 `""`,用户提供录屏后再补。
13. **时长**:`duration` = 去空白字数 ÷ `charsPerSecond`(默认 4),且不短于组件 `minDuration`,保留 1 位小数。

## 清单格式

```json
{
  "version": 1,
  "title": "视频标题",
  "theme": "neon",
  "charsPerSecond": 4,
  "scenes": [
    {
      "id": "s01",
      "script": "这个画面对应的口播原文(全部画面按顺序拼起来必须等于原稿,只允许空白不同)",
      "component": "dy-scene-title",
      "variables": { "kicker": "…", "title": "…", "em": "…", "sub": "" },
      "duration": 5.5,
      "overlays": [],
      "transitionIn": null,
      "needs": []
    }
  ],
  "newComponents": []
}
```

- `id` 从 `s01` 起连续编号。
- `overlays[]`:`{ "component", "variables", "at", "duration" }`。
- `transitionIn`:`null` / `dy-tr-wipe` / `dy-tr-zoom` / `dy-tr-glitch`。
- `needs[]`:`{ "type": "recording" | "image", "variable": "src", "hint": "录制:…" }`。
- `newComponents[]`:`{ "id", "status": "pending" | "accepted", "purpose" }`。

参考示例:`storyboards/example.json`(对应口播 `tests/storyboards/example-script.txt`)。

## 现有组件表达不了时:生成新组件

只有当现有组件都表达不好(例如时间线、逐年变化、思维导图),而且第 4 条规则也装不下时,才生成新组件。生成前再查一遍目录。

1. 严格按 `component-guide.md` 编写,写测试用例(normal / long / real),`node tests/run.mjs <id>` 4 个主题通过。
2. 清单里直接用它,并在 `newComponents` 写 `{ "id", "status": "pending", "purpose" }`。
3. 生成 4 主题对比图(`node tests/sheet.mjs <id>` 和 `--variant long`),连同用途、变量说明、适合的口播内容发给用户。**用户确认前不提交、不推送。**
4. 用户确认后按 `component-guide.md` 第 8 节入库,把状态改为 `accepted`;用户要修改就改完重发对比图;用户拒绝就删除组件,清单里改用现有组件。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 改写口播的字或标点 | `script` 原样切分,校验会逐字比对 |
| 推算数字(倍数、百分比、年度合计) | 只写口播里说出的数字 |
| 漏填 `note`、`source`、`cta` 等变量 | 每个显示文字的变量都写,不显示就写 `""` |
| 一个画面塞 10 秒以上的口播 | 拆成两个画面;录屏超过约 12.5 秒按步骤拆 |
| 一条时间线拆给快讯卡、步骤页、钩子标题 | 用一个组件讲完,或连续画面用同一组件 |
| 每个画面之间都加转场 | 只在换话题时加 |
